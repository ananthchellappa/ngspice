Four patches for an upstream maintainer, one directory per item. P4 (the
`rnddraws` draw log) is not here: it is fork work agreed with xschem, not an upstream fix.
`p4-crash/` is a different thing: the `.model` crash fixed in follow-up batch 2,
item 1 (`doc/codex/issues/0074`), which `pre-master-47` has too.

## What each patch leaves out, compared with `ver_51`

**P1.**
- `tests/regression/exitstatus/behav-r-model-warn.*`. That deck asserts the
  five new warnings on stderr under `tests/bin/check_status.sh`, a downstream
  harness. Upstream's `check.sh` never captures stderr, and its filter deletes
  `Warning` lines.
- The fatal-exit hook (`behav_r_models_root`, freed in
  `inp_netlist_read_reset()`). That function exists only in the fork. Without
  the hook, a `controlled_exit()` inside `inp_compat()` in `libngspice` leaks
  the model lists. Upstream already leaks the scope tree and the deck on that
  path.
- The fork's case-sensitive spellings. The fork's
  `model_name_match(a, b, !inp_case_exact_ids())` becomes upstream's
  `model_name_match(a, b)`, and `elem_letter(line)` becomes `*line`.
- One comment's reference to the fork's batch ("decision 4").
- The fork's `/* case-lint: stored - ... */` comment on the `strcmp()` that
  compares duplicate `.model` cards (follow-up batch 2, item 2). Upstream has
  no identity lint.
- Follow-up batch 2, item 2 (b): clearing `behav_r_models_root` before the
  normal-path free, and emptying `level->models` before its walk in
  `inp_free_models()`. Both only protect the fatal-exit hook above, which
  upstream does not have, so they change nothing there.
- The two cards that batch added to `behav-r-model-warn.cir` (r10, r11),
  with that deck. `temper-res-behav-dup.cir` covers the identical-cards case
  in `check.sh` form. The case where cards differ only warns, which
  `check.sh` cannot see.

**P2.**
- All of its tests. That is `tests/regression/rng/` (the `option-seed-*`
  decks, `option-seed-unusable.cir` among them), plus its `configure.ac` and `tests/regression/Makefile.am` lines and
  `check_status.sh`. They assert stderr, which no upstream harness can see.
- The fork's draw-log (P4) code in the same functions. That is the seed record
  and call counter in `randnumb.c`, the `rng_*` declarations, `drawlog.h` and
  the `ng_drawlog_*` calls.
- `eval_opt()`'s comparisons are left as upstream spells them (`strstr`/`eq`;
  the fork has `cistrstr`/`eqc`).

**P3.**
- `startup-equals-setseed1.cir`, which reports through its exit status under
  `check_status.sh`. It is replaced by `tests/regression/misc/startup-seed.cir`
  in `check.sh` form. That deck keeps the first draw in a control-language
  variable, so it also runs on 45.2, and fails there for the right reason.
- `setseed7-bit-identity.cir`, a glibc-only guard that the fork skips through
  a `.requires` file only `check_status.sh` reads, and that `.requires`
  support itself.
- The fork's P4 hunks in `sharedspice.c`.

**p4-crash.**
- Six of the seven decks in `tests/regression/exitstatus/` (`model-typeless-*`,
  `model-bare-*`). They assert exit status 1 and the error on stderr under
  `check_status.sh`. Under `check.sh` a crash and a clean exit 1 both leave
  stdout empty, so they cannot be told apart there.
- `model-typeless-if-dead.cir` is kept, rewritten in `check.sh` form as
  `tests/regression/model/model-typeless-if-dead.cir`: the deck must run, so
  a crash leaves its `INFO: success` out.
- `doc/codex/issues/0074-*.md`. The commit message carries its substance.
- The fix itself is unchanged. Without `p1`, the check is factored out of
  `inp_rem_unused_models()`, where `pre-master-47` has it. With `p1`
  (`on-p1/`), it is factored out of `inp_collect_models()`, as on `ver_51`.

**Does `pre-master-47` crash the same way?** Yes, from reading its code; it
was not built. `inp_expand_macro_in_str()` has the same
`findtok_noparen(&search_ptr, &search_ptr, &end)` followed by
`strchr(search_ptr, '(')`. `modtranslate()` has the same unchecked
`gettok()`, and `wl_find()` the same `eq()` on each word. `inp_readall()`
skips `inp_rem_unused_models()` for a deck with `.if`, before
`inp_expand_macros_in_deck()`, and `has_if` is set in one place and never
cleared. The code dates from `9e8e50cb5` (ngspice-32). ngspice-45.2 exits
139 on the five `.if` decks of `tests/regression/exitstatus/` and 1 on the
one without `.if`, the same as the fork before the fix.
