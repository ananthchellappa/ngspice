### Problems raised

1. FALSE LOAD-BEARING CLAIM (serious). Root Cause states: "`plot_cur` moves only through `plot_setcur()` (`src/frontend/vectors.c:1352`, assigning at `:1431`)". Refuted by grep: of 22 `plot_cur =` sites in src/, only four (vectors.c:1362, :1368, :1393, :1431) are inside plot_setcur(). The rest assign plot_cur directly: src/frontend/com_fft.c:140 and :373, src/frontend/spec.c:195, src/frontend/dotcards.c:208, :223, :268, :321, :349, :385, :402, src/frontend/postcoms.c:1092 and :1109, src/frontend/com_let.c:248 and :250, src/frontend/numparam/xpressn.c:1123 and :1125.

2. CONSEQUENCE OF THE ABOVE (serious). The Resolution proposes "a '`plot_cur` was chosen' flag ... set by `plot_setcur()` and `plotInit()`" and Acceptance criterion 1 requires it be set "by nothing else". I measured a path that defeats exactly that design: deck `op` / `destroy op1` / bare `write destroy.raw` (build-ver_50/src/ngspice -b -n, no -D) prints `curplot-before op1`, `curplot-after const`, and writes the SAME 570-byte constants raw (`Title: Constant values`, `Plotname: constants`). plot_cur was re-pointed at the constants plot by postcoms.c:1092 without going through plot_setcur(), while the flag would already read TRUE from the earlier plotInit(). The issue's own acceptance matrix has no row for this and its proposed fix would pass it through.

3. OVERSTATED TRIGGER (moderate). Summary asserts "The trigger is any `.save` that names something the run does not have." Measured false: deck `.save v(nosuchnode) v(In)` (build-ver_50, -b -n, no -D) exits rc=0 and writes a real 291-byte `Plotname: Operating Point` raw. The guard at outitf.c:461 fires only when EVERY .save name misses (numData==1 with a refIndex, or numData==0 without). The accurate trigger is "a .save whose names all miss" — or, per the issue's own bare-pipe measurement, no analysis having run at all, which involves no .save.

4. CITATION MISMATCH (moderate). Acceptance criterion 4 credits the fopen/`if $fh < 0` mechanism to "object selection (`src/xspice/verilog/vlnggen:249-261`)". That range is the *shim source file* location probe (`set shimfile` search over $sourcepath). vlnggen's object selection probe is at :327-333 (`set vcd_obj=...` / `fopen fh "$vcd_obj"` / `if $fh >= 0`). Right mechanism, wrong line range for the purpose named.

5. CITATION MISATTRIBUTION (minor). Acceptance criterion 1 says "`wl == NULL` after `postcoms.c:589-594`, the branch that substitutes the static `all`". Lines 589-594 are the branch that consumes the *filename* off the wordlist (`file = wl->wl_word; wl = wl->wl_next;` / `else file = ft_rawfile;`). The substitution of the static `all` is at :613-614, which the issue quotes correctly elsewhere. The appositive points at the wrong lines.
