# Phase 1 census — case-sensitive comparisons against lowercase literals

Deliverable 1.0 of `doc/claude/suggestions/case-sensitive-identifiers-plan.md`.
The plan refuses to cost Phase 1 until a mechanical census exists, because three
prior estimates of the surface disagreed by an order of magnitude (642, ~304,
~120). This is that census. It is the phase's unit of progress: one checkbox per
comparison site.

Generated by `doc/claude/scripts/census_case_literals.py`, run as

```sh
python3 doc/claude/scripts/census_case_literals.py \
    src/frontend src/spicelib/parser src/xspice
```

## What the script counts

**Pass A** — every call to `strcmp`, `strncmp`, `strstr`, `strcasestr`, `eq`,
`eqn` or numparam's `prefix` that has at least one string-literal operand
containing a lowercase ASCII letter and no uppercase one. Such a call can only
ever match text that has already been case-folded.

**Pass B** — every call to the same primitives with *no* string literal operand
at all. A literal scan cannot see these, yet several of the plan's named members
live there: the comparison is against a table field the build generates in
lowercase (`IFparm.keyword`, `Mif_Conn_Info_t.allowed_type_str[]`,
`Evt_Udn_Info_t.name`). Pass B is reported in full and classified by hand rather
than guessed at, so the enumeration stays mechanical.

Comments and string literals are lexed, so `strcmp` inside a comment or inside a
literal is not counted. Calls spanning several physical lines are reassembled.

### Known limits of the enumeration

- **Character-literal comparisons are not counted.** `*name == 'v'` is a keyword
  match too — it is the plan's own `inp2dot.c:366,387,489` — but a scan for
  `== '<lowercase>'` returns thousands of hits, almost all of them parser
  bookkeeping. Those sites are carried on the per-file checklists instead, as
  they are found while converting the file.
- Roots are the three directories the plan names. `src/misc`, `src/maths`,
  `src/spicelib/devices` and `src/osdi` are out of scope for Phase 1.
- Two calls on one physical line are two rows. 1003 rows cover 936 distinct
  `file:line` positions.

## Fold-visible subset — where a test can be written

In `fold` mode both operands of a converted comparison are already lowercase, so
case-insensitive and case-sensitive are the same predicate and the change is a
no-op that can be reviewed without running anything. That argument fails on text
that never went through `inp_read()`'s fold. `fold_visible` marks the rows where
uppercase can actually reach the comparison today:

- the interactive prompt, `ngspice -p` stdin and `ngSpice_Command()` — the cp
  shell input path does not call `inp_read()` at all. This is by far the largest
  source, and it is why `tests/regression/pipe/` is the only suite that can hold
  a RED test for most of this phase
- `.lib` and `.inc` cards, exempt unconditionally at `inpcom.c:1826`
- the print-redirection tail after `>` (`inpcom.c:~1806`)
- the token following `title`/`xlabel`/`ylabel` on a `plot`/`gnuplot`/`hardcopy`
  line
- the 13-command control whitelist, which since `455221ae4` also applies behind a
  `*#` prefix
- XSPICE `.model` cards matched by `is_xspice_model()` and CIDER model/`ic.file`
  lines — but only the text inside one quoted pair; everything outside the quotes
  on those lines is still folded
- shell variable values set with `setcs`, command-line arguments, environment
  variables, rawfile contents

### Correction to the plan's Phase 1 RED

The plan proposes `tests/regression/misc/keyword-case.cir` with `.TRAN 1n 10n
UIC` and states it is RED today. It is not. An ordinary card is lowercased in
place by `inp_read()` before the card structure exists, so `dot_tran()` already
receives `uic` and the deck passes on an unmodified tree:

```
.TRAN 1n 10n UIC   ->  v(out)[0] = 9.999990e-07   (UIC honoured)
.tran 1n 10n uic   ->  v(out)[0] = 9.999990e-07
.tran 1n 10n       ->  v(out)[0] = 1.000000e+00
```

The defect is real, but it is reachable only from the command line, which is not
folded — `com_tran` -> `dosim` -> `if_run` re-emits the wordlist as a `.tran`
card and pushes it through `INP2dot`:

```
tran 1n 10n uic   ->  v0 = 9.999990e-07
tran 1n 10n UIC   ->  Error: unknown parameter on .tran - ignored
                      tran simulation(s) aborted
```

So the RED for this phase is `tests/regression/pipe/analysis-keyword-case.cmd`,
not a `.cir`. The same correction applies to every keyword the plan lists under a
dot card.
